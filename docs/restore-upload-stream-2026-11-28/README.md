# Restore upload transport and event-loop isolation — 2026-11-28

Parent: `bd6028f300ae23f7e07ede9cd46bab2f99fad19d`. Its [PR CI run](https://github.com/YellowBrokeIt/LinkScribe/actions/runs/46144398932) completed successfully, with all three Unit and API jobs (Ubuntu, Windows, macOS) passing. This is parent evidence, not verification of the new candidate.

The old async route read the already-spooled multipart upload into a bytearray, copied it to bytes, and then performed synchronous ZIP/JSON validation and SQLite insertion on the ASGI event-loop thread. A real FastAPI multipart request carrying a 1,619,166-byte ZIP with 80 synthetic Greek records reproduced both the bytes input and identical loop/restore thread IDs. That can make the interface unresponsive during large restores even if recognition is not running.

The replacement synchronous FastAPI route runs in its worker pool, passes the existing seekable spool directly to ZIP validation, and closes that file on success or failure. The helper measures actual file length using seek before ZIP parsing rather than trusting multipart metadata. Existing byte callers remain supported. Empty and invalid archives remain HTTP 400; oversized uploads remain HTTP 413; cross-site POST rejection remains HTTP 403. Manifest checks, payload size, checksums, all row validators, duplicate rejection, version compatibility, skip-existing behavior and transaction ordering remain unchanged. The file helper does not close its caller-owned stream.

The exact added test source (FNV-1a b7a20bbd) passed **5 tests in 0.35 s**. This local probe does not test full production validators or production lifespan. The maintained tests use the complete application modules and isolated SQLite. The candidate removes the explicit full compressed-archive bytearray and bytes copies in the route; no total RAM or latency improvement has been measured. FastAPI still receives and parses the upload before the route runs; this is not an ingress limit. The uncompressed JSON document is still decoded as a whole. No translation, summary, speaker, provider or long-recording release gate is closed. Version remains 0.3.0.
