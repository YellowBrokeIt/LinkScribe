Before this change, each edit replaced all segments and title without checking whether a different browser tab or overlapping request had saved a newer version. It could silently erase a correction. The async endpoint also performed SQLite reads and full edit validation/writes synchronously on the event loop; unpaired Unicode surrogates could cause encoding failures. The updated browser submits the saved record's revision. The endpoint parses the body and moves synchronous work to a worker. It checks the revision before validation and again inside an SQLite BEGIN IMMEDIATE transaction, returning HTTP 409 for a changed snapshot. The exact committed revision is returned. The browser only adopts a matching follow-up GET and advances the revision for newer in-flight local edits, so they remain saveable; a conflicting saved revision leaves local edits intact and requests reload. Legacy clients without a revision retain their request format (overlap within a request is protected, but their earlier browser snapshots cannot be inferred). Invalid UTF-8 surrogate text is rejected without a write. Existing invalidation, warnings and batch title updates remain.
