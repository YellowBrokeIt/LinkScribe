# Demand-driven disk-backed batch archive — 2026-11-28

Parent: `76efd94c412a6dad2a4aad66d7b01f7ac7903c3d`. Its [PR CI run](https://github.com/YellowBrokeIt/LinkScribe/actions/runs/46154073783) completed successfully on Ubuntu, Windows and macOS. This is parent evidence only.

Previously the completion worker generated and saved a batch ZIP that the download endpoint never used, and the download endpoint built the full compressed archive in memory and wrapped it in another BytesIO. The new worker marks the durable journal complete once its items are acknowledged. The download creates a private OS-managed temporary file, writes the same members and manifest, streams 64 KiB chunks with Content-Length, and closes the owned file after ASGI completion or failure. Generation failure closes the file as well. Existing in-memory helper semantics are retained for explicit callers. No batch size, provider, model or content-quality gate is changed.

Direct Git checkout remained unavailable (DNS). A scoped Python probe exercised the exact changed archive writer, response, process and endpoint sections (FNV-1a cfb6eec0, aeca4271, bee9cf5c respectively, trailing whitespace excluded). It used FastAPI 0.128.2, Starlette 0.50.0, real SQLite JSON-backed simplified journal/library adapters, real ZIP/temporary files and actual ASGI requests. Export content, worker and job-completion helpers were simplified; this is not full application or real transcription verification. Six tests passed in 2.62 s: no eager archive, current Greek edits and mixed/deleted-item manifest, identical ZIP members across memory/disk paths, cleanup on generation and send failures, bounded chunks and normal closure, invalid/unready batch rejection, and synthetic benchmark equivalence.

For twenty synthetic records with deterministic high-entropy 512 KiB data encoded in text (two large repeated export components per record), archive size was 21,190,057 bytes. Peak traced Python allocations during generation were 27,612,626 bytes for the in-memory path and 4,450,019 bytes for the disk-backed path (83.9% lower); elapsed 0.980 vs 0.989 s. This measures the generated archive path with simplified export data, not total process RSS, client buffering, storage throughput, whole-app fit or actual speech recognition. The production response also no longer retains a full compressed ZIP in memory. Disk space is required while downloading. No new model/provider calls were made.

Four full-app regression cases are added to the maintained suite (lazy completion and edited output with actual API/journal/library, generation failure, normal/failing ASGI streaming). Their execution remains pending hosted CI. The existing restart, export and mixed-batch tests remain unchanged. Translation/summary meaning, broader ASR/speaker accuracy, restricted providers and long-recording/whole-machine fit remain unresolved. Version stays 0.3.0.
